---

প্রতিটি সমস্যাই বাগ (bug) নয়। আবার প্রতিটি বাগের জন্য ডিবাগিং করার প্রয়োজন হয় না।

এআই-অ্যাসিস্টেড ডেভেলপমেন্টের (AI-assisted development) ক্ষেত্রে কোনো কিছু ভুল হলে, আমাদের সহজাত প্রবৃত্তি হলো ক্রমাগত প্রম্পট করতে থাকা — সমস্যার বিবরণ দেওয়া, ফিক্স চাওয়া, আরেকটি ভাঙা বা ত্রুটিপূর্ণ ভার্সন পাওয়া, সেই সমস্যার বিবরণ দেওয়া এবং আবার ফিক্স চাওয়া। এর ফলে সেশন দীর্ঘ হতে থাকে। কনটেক্সট দূষিত (polluted) হয়ে যায়। কোডের মান আরও খারাপ হয়।

সমস্যাটি কোডের নয়। সমস্যাটি হলো আপনি কোন ধরনের ফেইলিউর বা ব্যর্থতার মুখোমুখি হয়েছেন তা না জানা।

এই স্কিল বা দক্ষতাটি প্রথমে ফেইলিউরটি ডায়াগনোজ করে। তারপর সঠিক সমাধানের পরামর্শ দেয়। এগুলো দুটি আলাদা ধাপ এবং এদের ক্রম পরিবর্তন করা যাবে না।

---

## ধাপ ১ — কী ভুল হয়েছে তা বর্ণনা করুন

ডেভেলপার সমস্যার বিবরণ দেবেন। অন্য কিছু করার আগে এই স্কিলটি মনোযোগ দিয়ে তা শুনবে।

জিজ্ঞাসা করুন:

```

Describe what is wrong. Be specific:

* What did you expect to happen?
* What happened instead?
* How many times have you tried to fix it already?

```

উত্তরটি মনোযোগ দিয়ে পড়ুন। সমস্যাটি সমাধানের চেষ্টার সংখ্যাটি অত্যন্ত গুরুত্বপূর্ণ — এটি আপনাকে জানাবে যে এটি একটি নতুন সমস্যা নাকি সেশনটি ইতিমধ্যে ভুল পথে চলে গেছে।

---

## ধাপ ২ — ফেইলিউর মোড (Failure Mode) শনাক্ত করুন

বিবরণের ওপর ভিত্তি করে নির্ধারণ করুন যে এটি এই তিনটি ফেইলিউর মোডের মধ্যে কোনটি।

### ফেইলিউর মোড ১ — একটি নির্দিষ্ট জিনিস ভেঙে গেছে বা কাজ করছে না

**লক্ষণসমূহ:**

- সমস্যাটি আইসোলেটেড বা বিচ্ছিন্ন — একটি মাত্র কম্পোনেন্ট, একটি ফাংশন বা একটি রাউটের মধ্যে সীমাবদ্ধ
- প্রজেক্টের বাকি অংশ সঠিকভাবে কাজ করছে
- এটি ঠিক করার জন্য প্রথম বা দ্বিতীয়বার চেষ্টা করা হচ্ছে
- এরর মেসেজ (Error message) বা ভুল আচরণটি স্পষ্ট এবং সুনির্দিষ্ট

**এর অর্থ কী:**
এটি একটি সাধারণ বাগ। এর একটি মূল কারণ বা রুট কজ (root cause) আছে যা সুনির্দিষ্টভাবে খুঁজে বের করে ঠিক করা সম্ভব।

**সমাধান বা রেসপন্স:** টার্গেটেড ফিক্স (Targeted fix) — ধাপ ৩A-তে যান।

---

### ফেইলিউর মোড ২ — সেশনটি ভুল পথে চলে গেছে

**লক্ষণসমূহ:**

- একাধিকবার ফিক্স করার চেষ্টা পরিস্থিতিকে আরও খারাপ করেছে বা নতুন সমস্যার সৃষ্টি করেছে
- কোডটি জটিল বা জট পাকিয়ে গেছে — ফিক্সের ওপর জোড়াতালি দিয়ে আরও ফিক্স করা হচ্ছে
- এই সেশনের কনটেক্সট ব্যর্থ চেষ্টায় ভরপুর হয়ে গেছে
- মূল সমস্যাটি আসলে কী ছিল তা এখন আর স্পষ্ট নয়

**এর অর্থ কী:**
সেশনটি দূষিত বা পলুটেড হয়ে গেছে। আরও প্রম্পট করলে কোনো লাভ হবে না — বরং ক্ষতি আরও বাড়বে। ফিচারটিকে একটি একদম ফ্রেশ বা পরিষ্কার কনটেক্সটে নতুন করে তৈরি করা দরকার, আর জোড়াতালি দেওয়া যাবে না।

**সমাধান বা রেসপন্স:** হার্ড রিসেট (Hard reset) — ধাপ ৩B-তে যান।

---

### ফেইলিউর মোড ৩ — ফাউন্ডেশন বা ভিত্তিটিই ভুল

**লক্ষণসমূহ:**

- কোডটি রান করছে কিন্তু সম্পূর্ণ ভুল আউটপুট বা আচরণ দেখাচ্ছে
- ক্লড (Claude) আত্মবিশ্বাসের সাথে এমন কিছু তৈরি করে গেছে যা কোনো মূল রিকোয়ারমেন্ট, লাইব্রেরি এপিআই (API), অথবা আর্কিটেকচারাল প্যাটার্নকে ভুল বোঝার কারণে হয়েছে
- সমস্যাটি ইমপ্লিমেন্টেশনের কোনো বাগ নয় — ইমপ্লিমেন্টেশন বা পদ্ধতিটি নিজেই ভুল
- আলাদা আলাদা অংশ ঠিক করে কোনো লাভ হবে না কারণ পুরো অ্যাপ্রোচ বা পদ্ধতিটিই ভুল

**এর অর্থ কী:**
এটি কোনো ডিবাগিংয়ের সমস্যা নয়। কোনো কোড লেখার আগে পুরো অ্যাপ্রোচটি নিয়ে আবার ভাবা দরকার। ভুল ডিরেকশনে বা ভুল পথে আরও বেশি ইমপ্লিমেন্টেশন করলে জট ছাড়ানো আরও কঠিন হয়ে পড়বে।

**সমাধান বা রেসপন্স:** নতুন করে ভাবা (Rethink) — ধাপ ৩C-তে যান।

---

সামনে এগিয়ে যাওয়ার আগে ডেভেলপারকে জানান এটি কোন ধরনের ফেইলিউর মোড:

```

This looks like Failure Mode [1/2/3] — [name].

[এটি কেন এই মোডে পড়েছে তা ব্যাখ্যা করে একটি বাক্য।]

Here is how we handle this:

```

## ধাপ ৩A — টার্গেটেড ফিক্স (Targeted Fix)

ফেইলিউর মোড ১-এর জন্য।

### কোডে হাত দেওয়ার আগে ডায়াগনোজ করুন

ডেভেলপারকে নিচের বিষয়গুলো শেয়ার করতে বলুন:

- সঠিক এরর মেসেজ বা ভুল আচরণটি কী
- নির্দিষ্ট কোন ফাইল বা ফাংশনে এটি ঘটছে
- কোডটির আসলে কী করার কথা ছিল বনাম এটি বর্তমানে কী করছে

সংশ্লিষ্ট কোডটি পড়ুন। পুরো কোডবেস পড়ার দরকার নেই — কেবল সমস্যার সাথে সরাসরি সম্পৃক্ত অংশটুকুই পড়ুন।

### মূল কারণ (Root Cause) খুঁজে বের করুন

যেকোনো ফিক্সের পরামর্শ দেওয়ার আগে মূল কারণ বা রুট কজ শনাক্ত করুন। রুট কজ হলো সমস্যাটি ঘটার আসল কারণ — কোনো বাহ্যিক লক্ষণ বা উপসর্গ নয়।

মূল কারণটি স্পষ্টভাবে উল্লেখ করুন:

```

Root cause: [এটি কেন ঘটছে তার সুনির্দিষ্ট ব্যাখ্যা]

This is different from the symptom because: [ব্যাখ্যা]

```

### একটি সুনির্দিষ্ট ফিক্সের পরামর্শ দিন

এমন একটি ফিক্সের বর্ণনা দিন যা সরাসরি মূল কারণ বা রুট কজকে সমাধান করে। কোনো সাময়িক ওয়ার্কঅ্যারাউন্ড (workaround) বা জোড়াতালি নয়। ভাঙা কোডের ওপর আরও প্রলেপ দেওয়া নয়।

```

Fix: [কী পরিবর্তন করা প্রয়োজন এবং কেন]

This will resolve the root cause because: [ব্যাখ্যা]

```

কোনো পরিবর্তন করার আগে ডেভেলপারের নিশ্চিতকরণের (Confirmation) জন্য অপেক্ষা করুন।

### যদি ফিক্সটি কাজ না করে

যদি প্রস্তাবিত ফিক্সটি সমস্যার সমাধান করতে না পারে — তবে থামুন। সাথে সাথেই আরেকটি ফিক্সের পরামর্শ দিতে যাবেন না।

রুট কজ ডায়াগনোসিসটি আবার পরীক্ষা করুন। ফিক্সটি কাজ না করার অর্থ হলো সম্ভবত মূল কারণটি ভুলভাবে শনাক্ত করা হয়েছিল। আবার চেষ্টা করার আগে শুরু থেকে নতুন করে ডায়াগনোজ করুন।

যদি পরপর দুটি রুট কজ ডায়াগনোসিস ভুল প্রমাণিত হয় — তবে এটি আসলে ফেইলিউর মোড ২ বা ৩ হতে পারে। বিষয়টি পুনরায় মূল্যায়ন (Re-evaluate) করুন।

## ধাপ ৩B — হার্ড রিসেট (Hard Reset)

ফেইলিউর মোড ২-এর জন্য।

### পরিস্থিতি সততার সাথে স্বীকার করুন

```

This session has gone too far in the wrong direction
to recover by patching. The right move is a clean start.

This is not a failure — it is the correct response
to a polluted context. A fresh session with clear intent
will be faster than continuing here.

```

### যা যা রাখার মতো তা সংরক্ষণ করুন

সেশনটি শেষ করার আগে, বর্তমান অবস্থা থেকে মূল্যবান যেকোনো কিছু এক্সট্রাক্ট বা সংগ্রহ করে নিন:

- মূল ফিচারটির আসলে কী করার কথা ছিল?
- বর্তমান ইমপ্লিমেন্টেশনের কোনো অংশ কি আদৌ সঠিক আছে?
- কোন জিনিসটি কাজ করে না সে সম্পর্কে কী জানা গেছে?
- পরবর্তী সেশনে কোন বিষয়টি এড়িয়ে চলা উচিত?

এটিকে একটি সংক্ষিপ্ত রিসেট নোট হিসেবে লিখুন:

```

## Reset Note — [ফিচারের নাম]

### আমরা কী তৈরি করছিলাম

[মূল ফিচারের বিবরণ]

### কী ভুল হয়েছে

[সেশনটি কীভাবে ট্র্যাক থেকে বিচ্যুত হলো তার একটি সৎ সারসংক্ষেপ]

### পরবর্তী সময়ে যা এড়িয়ে চলতে হবে

[নির্দিষ্ট কোনো অ্যাপ্রোচ বা প্যাটার্ন যা কাজ করেনি]

### পরবর্তী সেশনের শুরুর বিন্দু

[কোথা থেকে নতুন করে শুরু করতে হবে — কী রাখতে হবে, কী বাদ দিতে হবে]

```

### ডেভেলপারকে নির্দেশনা দিন

```

Next steps:

1. Save this reset note somewhere accessible
2. End this session completely
3. Start a fresh session
4. Begin with /remember restore if memory exists
5. Approach [feature name] again with the reset note as context

Do not continue in this session.

```

## ধাপ ৩C — নতুন করে ভাবা (Rethink)

ফেইলিউর মোড ৩-এর জন্য।

### ভুল অনুমানটি (Wrong Assumption) চিহ্নিত করুন

ভিত্তি বা ফাউন্ডেশন ভুল হওয়ার অর্থ হলো এমন কিছু ধরে নেওয়া হয়েছিল যা নেওয়া উচিত হয়নি। সেটি খুঁজে বের করুন।

```

The core issue is not a bug — it is a wrong assumption:

Assumed: [কী ধরে নেওয়া হয়েছিল]
Reality: [প্রকৃত সত্য বা বাস্তবতা কী]

This means the current implementation cannot be fixed
by patching. The approach needs to change.

```

### সঠিক অ্যাপ্রোচ বা পদ্ধতির প্রস্তাব দিন

সঠিক বোঝার ওপর ভিত্তি করে, অ্যাপ্রোচটি কেমন হওয়া উচিত ছিল তা বর্ণনা করুন:

```

Correct approach: [বর্ণনা]

Key difference from current approach: [বর্তমান পদ্ধতির সাথে প্রধান পার্থক্য]

What needs to be discarded: [যা কিছু বাদ দিতে হবে এবং উদ্ধার করা সম্ভব নয়]
What can be kept: [যা এখনও বৈধ বা রাখা সম্ভব]

```

### সাথে সাথেই নতুন করে তৈরি করা শুরু করবেন না

নতুন করে ভাবার বা রিথিংক করার ক্ষেত্রে কোডে কোনো পরিবর্তন আনার আগে ডেভেলপারের সেটি বোঝা এবং তাতে সম্মত হওয়া প্রয়োজন। অ্যানালাইসিসটি বা বিশ্লেষণটি উপস্থাপন করুন এবং কনফার্মেশনের জন্য অপেক্ষা করুন।

```

Does this diagnosis match your understanding?

If yes — we can start fresh with the correct approach.
If no — tell me what I am getting wrong.

```

ডেভেলপার নিশ্চিত করার পরেই কেবল নতুন করে তৈরির কাজ (Rebuilding) শুরু হবে।

---

## মূল নীতি (The Rule)

কোনো কিছু ভেঙে গেলে বা কাজ না করলে সবচেয়ে খারাপ যে কাজটি আপনি করতে পারেন তা হলো — একই ভুল কাজ আরও দ্রুত গতিতে করতে থাকা।

প্রথমে ডায়াগনোজ করুন। সঠিকভাবে রেসপন্স করুন। ভিন্ন ভিন্ন ফেইলিউরের জন্য ভিন্ন ভিন্ন সমাধানের প্রয়োজন হয় — আর আপনি কোন ধরনের ফেইলিউরের মুখোমুখি হয়েছেন তা জানতে পারাটাই সমাধানের অর্ধেকেরও বেশি।
