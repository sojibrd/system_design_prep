Concurrency vs Parallelism

ওয়ার্কবুক 1.4.1 — একদিকে main thread ব্লক করে ভারী কাজ, আরেকদিকে Web Worker দিয়ে সমান্তরাল
⏱ পেজ জীবিত আছে: 0.0s

উপরের কাউন্টারটা প্রতি ১০০ms-এ বাড়ে — যদি এটা থেমে যায়, বুঝবেন main thread ব্লক হয়ে গেছে। ইনপুট বক্সে টাইপ করেও পরীক্ষা করতে পারেন।

🔴 Main Thread ব্লক করে (Synchronous)

একটা ভারী loop সরাসরি main thread-এ চালানো হবে — পুরো পেজ ততক্ষণ জমে থাকবে, কাউন্টার থেমে যাবে, টাইপ করা যাবে না।

প্রস্তুত

🟢 Web Worker দিয়ে (Parallel)

একই ভারী কাজ একটা আলাদা থ্রেডে (Web Worker) চালানো হবে — main thread মুক্ত থাকবে, কাউন্টার চলতেই থাকবে, টাইপ করা যাবে স্বাভাবিকভাবে।

প্রস্তুত
Concurrency মানে একটা থ্রেড অনেকগুলো কাজের মধ্যে দ্রুত সুইচ করে করে সবগুলোকে "এগিয়ে নেওয়া" (যেমন JS event loop — async/await, callbacks)। Parallelism মানে সত্যিকারের একসাথে চালানো — আলাদা CPU core/থ্রেডে (Web Worker, multi-core সার্ভার)। বাম দিকের ডেমো single-thread ব্লক করে দেখায় কেন heavy CPU কাজ main thread-এ করা উচিত নয় — ডান দিকের ডেমো দেখায় worker দিয়ে কীভাবে এটা এড়ানো যায়।
