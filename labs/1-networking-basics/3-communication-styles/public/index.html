Polling vs Long Polling vs SSE vs Webhook

ওয়ার্কবুক 1.3.1 — Network tab (DevTools) খুলে দেখুন request pattern কতটা আলাদা
🧒 সহজ ভাষায়

তুমি গাড়িতে বসে আছো, আম্মুর রান্না হচ্ছে বাসায়। কখন খাবার রেডি হবে জানতে চাও — চারটা ভিন্ন উপায়ে:

Polling: প্রতি ১ মিনিটে ফোন করে জিজ্ঞেস করা "রেডি হয়েছে?" — বেশিরভাগ বারই উত্তর আসে "না এখনো"।
Long Polling: একবার ফোন করে লাইনে থেকেই অপেক্ষা করা, যতক্ষণ না আম্মু বলে "হ্যাঁ রেডি!"।
SSE: আম্মু ফোনের লাইন খোলাই রেখেছে — রেডি হলেই নিজে থেকে বলে দেবে, তোমাকে জিজ্ঞেস করতেই হবে না।
Webhook: রেস্টুরেন্ট থেকে অর্ডার করেছো, তারা এসএমএস পাঠাবে "আপনার খাবার রেডি" — তুমি একদমই বসে অপেক্ষা করছো না, নিজের কাজ করছো, ওরাই জানাবে।

1️⃣ Polling

📞 বারবার ফোন করে জিজ্ঞেস করা "রেডি হয়েছে? রেডি হয়েছে?"

প্রতি ১.৫ সেকেন্ডে নতুন request পাঠানো হয় — বেশিরভাগ বারই "PREPARING" ফেরত আসে (অপচয়)

Requests: 0

2️⃣ Long Polling

☎️ একবার ফোন করে লাইনেই থেকে যাওয়া, উত্তর না আসা পর্যন্ত

একটা request পাঠানো হয়, সার্ভার "READY" না হওয়া পর্যন্ত ধরে রাখে — তারপর নতুন request

Requests: 0

3️⃣ SSE

📻 লাইন খোলা রাখা — রেডি হলে ওপাশ থেকেই বলে দেবে

একটাই connection খোলা থাকে — সার্ভার নিজে থেকে push করে, নতুন request লাগে না

Connections: 0

4️⃣ Webhook

📱 রেস্টুরেন্ট থেকে এসএমএস আসবে "খাবার রেডি" — তুমি বসে অপেক্ষা করছোই না

একটা ইভেন্ট ট্রিগার করুন ("পেমেন্ট")— সার্ভার নিজে থেকেই ২-৪ সেকেন্ড পর জানাবে

Triggers: 0
লক্ষ্য করুন: Polling প্যানেলে request count খুব দ্রুত বাড়ে (বেশিরভাগই খালি হাতে ফেরে)। Long Polling-এ request কম কিন্তু প্রতিটা কয়েক সেকেন্ড আটকে থাকে। SSE-তে একটামাত্র connection খোলা থাকে সারাক্ষণ। Webhook-এ ক্লায়েন্ট আদৌ পোল করেই না — সার্ভার নিজে থেকে জানায়।
